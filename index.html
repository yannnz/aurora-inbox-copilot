    Improvement · E-04
    Known limitations

    Scope decisions for this prototype — not a full product claim.

    1. Handles Ren’s morning email triage for fictional Aurora Materials by default (Demo inbox). Optional Gmail mode can read your real inbox and save reply drafts — still never auto-sends. No CRM or dashboards.
    2. Demo mode: English synthetic emails in this project’s CSV/record shape. Gmail mode: live threads via Gmail API (requires Google Cloud Gmail API + reconnect OAuth). Chinese WeChat and messy free-text outside email are out of scope.
    3. The agent triages one email at a time, with same-sender morning emails included only as context for duplicate/related detection. Run All is sequential demos, not parallel production throughput.
    4. Urgency uses the operator’s real current time (injected into worker/reviewer/chat prompts). Demo emails may still be dated May 2026 in the story data. Aurora CAL-* / flight rows stay synthetic context. Real Google Calendar create and Gmail draft sync only happen after you Approve with the matching checkbox. Gmail sync loads the last 7 days of inbox (cap 150).
    5. Needs a browser API key (and the local proxy for DeepSeek). Privacy: when you Run triage on Gmail messages, email bodies go to the public LLM APIs you configured (DeepSeek/OpenAI). Drafts stay suggestions until Approve — Gmail draft sync writes a draft only, never calls send.
